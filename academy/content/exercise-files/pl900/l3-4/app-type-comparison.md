## Part 2: classify each scenario
Write Canvas, Model-driven or Code app.

1. Field technicians inspect projectors in 40 classrooms on a phone, with photos and a checklist. Data is in SharePoint. ____
2. The help desk manages tickets, categories, SLAs and a business process flow. All data is in Dataverse. ____
3. The web team has a React and TypeScript design system and wants to reuse it, with Dataverse data and platform governance. ____
4. A kiosk tablet at reception lets visitors sign in with a custom branded screen. ____
5. Staff need the same look and navigation across 12 related Dataverse tables, on desktop and tablet. ____
6. Developers want full control of the UI in Visual Studio Code but must obey the tenant data policies. ____
7. A student check-in app combines an Excel file on OneDrive and a SQL Server table. ____
8. A back-office CRM with dashboards and views, built fast by a maker with no coding skills. ____

## Answer key (check after you finish)
**Part 1**
| | Canvas app | Model-driven app | Code app |
|---|---|---|---|
| Who builds it | Makers (low-code) | Makers (low-code) | Professional developers |
| How it is built | Drag controls onto screens, Power Fx formulas | Choose tables, forms, views, charts; layout is generated | Write code (for example React with TypeScript) in an IDE |
| Data sources | Many connectors: Dataverse, SharePoint, Excel, SQL and more | Dataverse | Connectors and Dataverse through generated client libraries |
| Layout control | Full, pixel by pixel | Limited, responsive by default | Full, in code |
| Best for | Task-focused and mobile apps, several data sources | Process-heavy apps on Dataverse | Custom web UI by teams with web skills, still governed |
